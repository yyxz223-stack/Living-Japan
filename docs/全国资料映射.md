# 全国资料、地图与正文映射

本轮日期：2026-10-29。实现入口：`scripts/build-national.mjs`、`src/catalog.js`、`src/national-worker.js`、`src/national-map.js`。回溯标记：`LJ-NATIONAL-01`、`LJ-NATIONAL-MAP-01`。

## 输入和保全范围

- 内部正文与既有身份来自正式 Living Japan v3.6；全国资料生成器不读取未验收站点稿、并行研究稿或旧地图人物、任务、室内剧情。
- 地图输入是日本全域地图 v3.0.0 的真实分区 bin。保留 48 个地理分区的 4,156,953 条展示记录，其中 `japan-v3` 与 `tokyo-v2.2` 两个原命名空间继续分开。这是来源展示记录数，不是全国唯一实体数量。
- 服装包只提取 `JPF-DATA:v1` 中门店、品牌身份和出处，不运行原服装助手/EJS。47 个门店分包共有 12,656 个独立源 ID；3,475 条有原坐标，9,181 条只有地址。未定位门店仍可检索、阅读身份、保存自己的正文。
- 原始 PBF 不写入扩展仓库、不由浏览器解析。其名称、大小和后续离线用途保存在 `data/national/sources.json`；现有构建没有对它做重解析。后续 PBF 处理属于独立来源流程。
- 地图来源记录、逐门店来源/日期/地址核对字段、原地图 `licenses` 均随必要数据保留。

## 实体和行政关系

统一实体的基本字段是 `id/name/aliases/type/adminPath/adminNodes/coordinates/source/legacyPlaceId/packageIds/regionCode/bodyStatus`。地点、行政节点、类别、正文是不同概念；地图有坐标不代表有正文。

| 来源 | 身份 |
|---|---|
| 既有正式正文对象 | 原 `placeId`，正文继续指向原 packageId 与 P/V 编辑槽 |
| 全国 POI | `map:<database_namespace>:<database_id>`，保留负数建筑编号 |
| 旧 POI 的数据库编号为 0 | 命名空间＋来源坐标、名称、地址、子类别组成来源记录键 |
| 服装门店 | `clothing:<原 s_… ID>`，多品牌关联保留在 brandIds |
| 官方铁路站点 | `rail:<原站点 ID>`；仅已核定站点对照表可以关联既有正文 |

不会按同名、同址、距离接近或相同数字编号跨来源合并。编号为 0 的旧记录缺少永久上游主键，其键在本来源快照不变时稳定；将来改源需要明确身份迁移对应，不能悄悄把旧用户稿改挂到猜测的新地点。

行政根为 `admin:jp`。共有 1,973 个行政节点，含 47 都道府县以及源中给出的市、区、町、村和所属未定地。政令市下的区保留市父级；源没有独立官方市代码的市容器使用带府县与日文市名的稳定 ID，不伪造数字代码。

能确定对应关系的节点复用 v3.6 原行政 ID，如 `pref_tokyo`、`tokyo_chiyoda`。来源名称不同的情形使用 v3.6 已有行政别名对应；不把旧源中没有任何地点挂载的重复名称节点另造为全国实体。既有站点以 `stationAdministration.officialAdminPathsJa` 为准，避免把旧 `transitStationAdditions.adminPath` 中的展示错误照搬进新树。

`adminPath` 是从日本根到所属行政节点的 ID 数组，不含地点自己。`adminNodes` 同时提供标签、类型与父 ID，供用户自建正文沿用行政父控。生活带可跨行政区；同对象多篇正文、设施包含关系仍由正式对象/正文关系保存，不把它们解释成行政上下级。无法确定具体市区的来源记录只落到可确定层级，不编造更细归属。

## 运行分块

- `manifest.json` 是轻量目录，列出地区骨架、空间块、记录数、来源哈希、行政树及版本。
- 48 个地区骨架只带地图几何、铁路站线等必要内容。POI 分为 1,001 个空间块，先按空间网格、再按较长坐标轴二分；每块最多 19,977 条，当前最大压缩块 815,323 字节。
- 默认 `metro` 是首都圈轻量视图，组合东京、神奈川、埼玉、千叶主大陆视野。压缩大小 904,892 字节；它不把四县的 POI 全部装进内存，也不把东京都含离岛全域冒称首都圈。
- 地区骨架缓存最多 2 份，并以 128 MiB 原始 JSON 字节数再限制；POI 块缓存最多 4 块。原始 JSON 字节预算不等于 JavaScript 实际堆内存。
- 浏览器使用独立 Worker 读取、解压、解析及检索。主线程只得到有限搜索结果、树分页和视野点；行政树展开只读 `adminChildren()`，不请求各县明细。
- 地图每次只画可见范围内的有限点；超精细视野只读取相交空间块。首都圈跨县查看时加载当前细部县包，国家/地区目录保持可切换。

## 四种地图与操作

旧地图 v3.0.0 的 `MODES` 明确为 `schem/map/detail/ultra`，不能改成四档密度。本实现保留独立的 `setMode()` 与密度 `setDetail()`。

| 模式 | 表现 |
|---|---|
| schem 示意 | 首都圈使用正式 v3.6 的 6 条线路、145 个站点拓扑；其他地区显示该地区铁路示意 |
| map 地图 | 真实行政轮廓、水系、公园及简化的主要铁路显示 |
| detail 精细 | 真实地理与完整铁路，并在视野中显示站点 |
| ultra 超精细 | 在真实底图上按空间块读取地点，并在街道范围显示道路 |

`select(entity, {locate:false})` 只选对象；独立 `locate(entity)` 只移动视野，不改变当前选择、不触发 onSelect。默认 `select(entity)` 兼容带定位的调用，UI 应按入口语义显式传参。双击/触屏双点只调用一次 onAppend；输入框保留和是否发送由宿主追加接口负责。

拖动、滚轮/双指缩放、选中、当前地区、路线端点分别保存。快切地区以请求序号丢弃过时绘制。`setRoute()` 当前绘制明确标注的端点连线，不把它称为真实导航；耗时和交通备注交由正式 v3.6 交通模块处理。

## 接口

- `createCatalog({baseData,baseUrl,fetcher})`：异步 `loadIndex/loadRegion/search/children/resolve/viewport`；同步 `get/adminChildren/navigationChildren/navigationPath/regions/projection/stats`。`workerStats()` 可读取 Worker 的缓存状态。
- `children(id,{offset,limit})` 默认分页 100 项，最多 500 项；用于地点列表，也支持浏览根和大区分组的分页。官方行政子级仍可用同步 `adminChildren(id)`。
- `get(id)` 返回已访问实体；刷新后恢复未缓存的用户对象可用 `resolve(id,{regionCode})`。内置正文不依赖地区地图已加载。
- `createNationalMap(container,{catalog,onSelect,onAppend,onError})`：`setRegion/select/locate/setMode/setDetail/setRoute/zoom/fit/getView/setView/destroy`。不另加一套 UI 按钮，使用已确认模板预留控件。

## 地理浏览分类（2026-10-29）

浏览顶层直接是北海道、东北、关东、中部、近畿、中国、四国、九州·冲绳，不显示日本根。47 个都道府县分别为 1、6、7、9、7、5、4、8 个，每县只属于一个浏览分组。

县归属参考[国土地理院都道府县选择表](https://vldb.gsi.go.jp/sokuchi/level/KENSOKUSYUROKU/todofuken.htm)，按本扩展的八组约定将其北陆并入中部；三重归近畿，山梨、长野归中部，冲绳归九州·冲绳。这只是浏览分类，官方 `admin:jp`、行政节点 ID、`adminPath`、`parentId`、EX/IN 父控和正文资格均保持原样。

`manifest.navigationRegions` 每组为 `{id,code,name,regionCodes}`，ID 使用 `navigation:` 命名空间。`catalog.navigationRoot` 是隐藏的 `navigation:root`；`navigationChildren()` 返回八组，传组 ID 返回该组都道府县，传行政 ID 返回真实行政子级。`navigationPath(id)` 返回可直接绘制的实体数组，包含目标行政节点，排除 `admin:jp`。分组实体标记 `type:'地理大区'`、`kind:'navigation-region'`、`browseOnly:true`，不作为可创建正文的行政对象。

地图 `regions()` 继续返回平表，仅为 47 县追加 `groupId/groupCode/groupName`，首都圈和全国视图独立。此次只为目录追加分类元数据，没有重建空间块；`adminNodes`、`regions`、`views` 内容在改前改后校验一致。

## 有限验证和实测边界

全国模块 16 项检查覆盖来源 ID 隔离、行政层级、原门店数、未定位记录、名称/别名/类型搜索、空正文、分包哈希、分页、Worker 初始化失败传播、快切地区、单/双击与定位语义。最后一次全项目 `npm test` 为 39/39 通过。

此后新增地理分类的 2 项检查：八组完整覆盖 47 县且无重复、隐藏日本根、官方父子关系保持、地图分组字段和仅索引浏览。两项先失败后通过；本次只复跑 build/catalog 相关检查，未把先前 39 项结果当作新界面的实机验证。

一次本机 Node 隔离读取实测：首都圈骨架约 81 ms，东京骨架约 50 ms；东京一个约 6.5×9.8 km 的超精细视野首次请求 13 块、返回 500 点，约 370 ms。该进程含正式基准资料，读完骨架时堆约 110 MiB，完成该视野后约 179 MiB；这是当次进程观测，不是持续内存上限。

此前整县一次解析方案的同机东京首次读取约 747 ms、进程堆约 457 MiB，已被空间分块替代。以上不是浏览器网络、真实 SillyTavern、手机、模型注入或帧率验收；这些由整合验证另行记录，不把 Node 测量写成实机完成。
